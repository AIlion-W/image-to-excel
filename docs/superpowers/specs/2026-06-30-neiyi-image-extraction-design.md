# 内衣图片提取模式设计

## 背景

当前项目是图片转 Excel 工具，已有「百货」「服饰鞋帽」「自定义」三种识别模式。用户新增一种内衣商品图片样式：商品图上覆盖大号文字，包含货号、尺码、外箱容量和意向价。该样式需要作为独立内置模式使用，避免影响已有百货和服饰鞋帽识别规则。

样例图片中的关键信息如下：

- `M010#`：货号，对应 Excel 字段「产品编号」
- `M L XL`：尺码，对应 Excel 字段「做货要求一」
- `1500*3.7`：`*` 前为外箱容量，`*` 后为客户意向价

样例期望输出为一行数据：

| 产品编号 | 外箱容量 | 客户意向价 | 做货要求一 | 箱    数 | 做货要求二 |
| --- | --- | --- | --- | --- | --- |
| M010# | 1500 | 3.7 | M L XL |  |  |

## 目标

新增独立内置模式「内衣」。用户选择该模式并上传图片后，系统按内衣图片规则提取字段，显示在现有结果表格中，并通过现有 Excel 导出链路下载。

## 非目标

- 不改现有「百货」「服饰鞋帽」「自定义」模式的行为。
- 不新增数据库、登录、存储或独立 API。
- 不修改 Excel 首列表头，继续沿用当前项目的「图片」列。
- 不按图片中的颜色、摆放件数、吊牌数量拆分多行。
- 不把颜色、款式、花型等视觉信息纳入本次提取范围。

## 用户流程

1. 用户在模式选择区选择「内衣」。
2. 用户上传一张或多张内衣商品图片。
3. 前端沿用现有图片压缩逻辑，把图片转成 base64。
4. 前端调用 `/api/extract`，传入 `mode=neiyi`。
5. 服务端加载 `lib/prompts/neiyi.md`，调用现有模型适配层。
6. 模型返回一张图片一条记录的 JSON。
7. 前端用现有 `ResultTable` 展示结果，用户可手动修正。
8. 用户点击下载 Excel，系统沿用现有 `/api/generate-excel` 导出。

## 架构设计

采用现有 prompt-driven 架构新增模式，不新增专用接口。

需要调整的模块：

- `components/PromptInput.tsx`
  - `Mode` 新增 `neiyi`
  - `LABELS` 新增 `neiyi: "内衣"`
  - `ORDER` 把 `neiyi` 放入内置模式按钮
- `lib/serverPrompts.ts`
  - `PromptMode` 新增 `neiyi`
  - `FILES` 新增 `neiyi: "neiyi.md"`
- `lib/prompts/neiyi.md`
  - 新增内衣图片识别规则
- 页面文案可小幅调整，让首页描述覆盖货号、容量、单价、尺码

## 字段规则

内衣模式固定输出以下 6 个字段，不输出「图片」字段。图片列由 Excel 导出逻辑自动嵌入。

| 字段 | 是否必填 | 规则 |
| --- | --- | --- |
| 产品编号 | 必填 | 提取图片中末尾带 `#` 的货号，如 `M010#`。保留 `#`。 |
| 外箱容量 | 必填 | 提取 `*`、`×`、`x`、`X` 前面的数字，如 `1500*3.7` 提取 `1500`。 |
| 客户意向价 | 必填 | 提取 `*`、`×`、`x`、`X` 后面的数字，如 `1500*3.7` 提取 `3.7`。 |
| 做货要求一 | 必填 | 提取尺码组合，如 `M L XL`。没有尺码时填 `均码`。 |
| 箱    数 | 固定空 | 始终输出空字符串，不默认填 `1`。 |
| 做货要求二 | 固定空 | 本次暂不提取额外信息，输出空字符串。 |

## 识别优先级

1. 优先使用图片上覆盖的大号文字。
2. 产品编号优先取带 `#` 的货号。若吊牌中存在 `NO:M010`，但覆盖文字存在 `M010#`，输出 `M010#`。
3. 尺码优先取覆盖文字中的 `M L XL`、`L XL`、`XL` 等尺码组合。
4. 外箱容量和客户意向价优先取同一段 `数字*数字` 结构，支持 `*`、`×`、`x`、`X`。
5. 一张图片只输出一行，即使图片里有多个颜色、多个实物或多个吊牌。

## 异常处理

- 能看出字段但不确定时，在值后追加 `(?)`，如 `M010#(?)`、`3.7(?)`。
- 完全看不到必填字段时填 `[待确认]`。
- 看不到尺码时不要填 `[待确认]`，按业务规则填 `均码`。
- `箱    数` 和 `做货要求二` 不参与异常补全，始终留空。
- 若模型看到多个可能货号，优先选择大号覆盖文字中带 `#` 的货号；只有没有覆盖货号时，才参考吊牌编号并补上 `#(?)` 标记。

## 测试与验收

代码验证：

- 运行 `npm run lint`。
- 如依赖环境允许，运行 `npm run build`。

人工验收：

- 用样例图片测试「内衣」模式。
- 页面表格应只出现一行结果。
- 期望字段为：
  - 产品编号：`M010#`
  - 外箱容量：`1500`
  - 客户意向价：`3.7`
  - 做货要求一：`M L XL`
  - 箱    数：空
  - 做货要求二：空
- 下载 Excel 后，首列仍为「图片」，后续列顺序跟页面表格一致。

## 实施风险

- 模型可能把吊牌上的 `NO:M010` 当成产品编号并漏掉 `#`。prompt 必须明确覆盖文字优先、带 `#` 优先。
- 模型可能把 `1500*3.7` 误分成尺码或其他备注。prompt 必须把乘号前后字段映射写成最高优先级。
- 模型可能因为图中多件商品输出多行。prompt 必须明确一图一行，不按颜色或吊牌拆行。
